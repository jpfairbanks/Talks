# Talks

Slide decks, as I want them to appear to the world. Each directory is one talk.

This is a living resource, not an archive. A deck can be improved after it has
been given — fix a wrong citation, redraw a figure, take a newer reveal.js — and
the version here is the one that counts. Decks are not preserved as they looked
on the day, and an upgrade that shifts the rendering slightly is fine.

Talks stay listed. Improve them, don't delete them.

## Where the decks come from

The pages here are built, and checked in as built, so GitHub Pages serves this
repository as it is — no build step. Don't edit them by hand: the next build
overwrites them.

They are generated by Hugo from the talk sources in
[`GATASLab/fairbanks-talks`](https://github.com/GATASLab/fairbanks-talks)
(private), from one library of slides. There, each slide is one file, and a talk
is a list of slide names, so a slide the talks share exists once and a fix to it
lands in every talk that uses it. The look is the lab's Hugo theme, from
[`GATASLab/talk-builder`](https://github.com/GATASLab/talk-builder) (private),
on [reveal-hugo](https://github.com/joshed-io/reveal-hugo). The sources' README
says how to build: with this repository checked out beside them, `hugo` there
writes here.

## Layout

Rendering dependencies and slide assets are served from here rather than loaded
from a CDN, so a deck presents with no network connection and does not break
when an upstream version is withdrawn. They are pooled at the repository root
and shared by every deck, which reaches them by a relative path (`../../../../assets/…`
from a deck four folders down):

```
assets/                     figures, photos, video, brand marks — kept here, not built
reveal-js/                  reveal.js 5.1.0, as reveal-hugo ships it: core, notes, highlight
vendored/katex-0.16.11/
vendored/fira-sans-2026-09/ a Google Fonts snapshot, dated rather than versioned
_ds/…-7193341c-…/           design system, keyed by its own id
gatas-talks/                the theme's stylesheet and script
css/site.css                the talks' own components (COE thrusts, plans, timeline)
index.html                  the list of talks
<yyyy>/<mm>/<event>/<surname>-<topic>/index.html
                            a deck, filed by when and where it was given, e.g.
                            2026/09/gt-dcl/fairbanks-sheaves-coordination/
j0pprb/index.html           the COE kickoff's old unlisted address, redirecting
```

Everything but `assets/`, the READMEs and `link_check.py` is build output. The
pooled `assets/` are the one source that lives here: a new figure for a deck goes
straight into `assets/`, and the builder refers to it from the site root.

A deck directory holds only its `index.html`, plus a `README.md` where a talk
has details worth recording. Its path is its public URL, so it is settled before
a talk is published and not renamed after. Because the assets live at the root, a deck
directory is not portable on its own — serve or publish the repository root.

## Upgrading a vendored library

The versions are named once, in the theme in the builder, and the next build
writes the new paths here. Drop the new build in beside the old one there, point
the theme at it, rebuild, run `./link_check.py`, and look at the decks. The old
directory here is then unused: `./link_check.py --versions` confirms it before
it is deleted.

## Checking the decks

`link_check.py` reads every page, follows the stylesheets it loads, and verifies
that every reference resolves and every asset is intact — a file that exists but
is truncated or of the wrong type is reported too, since it fails to display just
the same. External links are requested; hosts that refuse `HEAD` are retried with
`GET`. Standard library only, no install.

```sh
./link_check.py               # everything
./link_check.py --offline     # local files only, no network
./link_check.py --versions    # which deck uses which vendored version
./link_check.py --orphans     # files nothing references
./link_check.py --quiet       # only problems; exits non-zero if any
```

## Adding a deck

1. In the talk sources, add the talk: a directory
   `content/<yyyy>/<mm>/<event>/<surname>-<topic>/` holding an `_index.md` that
   lists its slides, reusing the library's where it can.
2. Add any new asset to the pooled `assets/` here.
3. Build, then add a row to the table above.
4. Run `./link_check.py`, and commit the built pages here.

Hugo only adds and overwrites here. A deck moved or dropped in the sources leaves
its old directory behind, to be removed by hand (`git rm -r`).

## Viewing a deck

Serve the repository root — not a single deck directory, since the assets are
pooled a level up:

```sh
python3 -m http.server 8000
```

Then visit `http://localhost:8000/2026/08/mae-seminar/fairbanks-compositional-methods/`.

Decks are [reveal.js](https://revealjs.com): arrow keys navigate, `Esc` shows
the slide overview, and `S` opens the speaker view.

## Note on `.nojekyll`

The `.nojekyll` file at the root is required. The design system lives in `_ds/`,
and GitHub Pages' Jekyll pipeline strips underscore-prefixed paths unless Jekyll
is disabled. Without it, decks render unstyled.

The trade-off is that Jekyll never renders this README into a landing page, so
`index.html` at the repository root is built along with the decks.
